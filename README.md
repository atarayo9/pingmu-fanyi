# 屏幕翻译

Windows 桌面小工具,框选屏幕上的文字就能翻译。两个功能:

- **📷 截屏翻译** —— 框一块区域 → 识别 → 翻译。原文可以直接改,改完重译,不用重新框选;
- **🎯 实时翻译** —— **先框一块区域**,之后持续识别 + 翻译,译文显示在悬浮窗里,
  位置、透明度、颜色、字号都能调。适合看视频字幕、游戏对话、直播。

翻译引擎和 OCR 引擎都可以换。免费的开箱即用;需要 Key 的会直接跟你要 Key,
并在输入框下面给出**申请 Key 的网址**。

## 安装与运行

需要 Python 3.9+(Windows)。

```
pip install -r requirements.txt
python main.py
```

---

## 一、实时翻译

1. 点主界面绿色 **「🎯 实时翻译」**(或按 `Ctrl+Shift+X`);
2. 主窗口自动隐藏,屏幕上出现半透明遮罩,**框住字幕/文字所在的那一小块**即可
   (框小一点更快更准,松开鼠标立刻开始);
3. 之后持续识别这块区域,翻好的文字显示在**译文悬浮窗**里;
4. 画面没变化时不会重复请求接口,同一句话再次出现会直接命中缓存,基本不额外消耗额度。

### 悬浮窗上能改什么

| 想改的东西 | 怎么改 |
| --- | --- |
| **显示位置** | 拖动悬浮窗顶部控制条;「🎨 样式 → 放回选区下方」复位 |
| **透明度 / 字号 / 宽度** | 「🎨 样式」里调;宽度也可以拖右下角 `◢` 拉手 |
| **字体颜色 / 背景颜色** | 「🎨 样式」里用调色板选 |
| **监视范围框** | 顶栏「👁 范围」一键开关,或「🎨 样式 → 监视范围框」勾选框 |
| **范围框颜色** | 「🎨 样式 → 范围框颜色」 |
| 是否同时显示原文 | 「🎨 样式 → 同时显示原文」 |
| 鼠标穿透(不挡操作) | 「🎨 样式 → 鼠标穿透」 |
| 刷新快慢 | 「🎨 样式 → 刷新间隔」,0.3~3 秒。越小越实时,越吃 CPU |
| **联系上下文翻译** | 「🎨 样式 → 上下文与速度」(仅大模型引擎有效) |
| **逐字显示** | 「🎨 样式 → 上下文与速度」 |

### 看得见在翻哪一块

框选完之后,屏幕上会用一圈**高亮边框**把这块区域标出来,顶上一条小标签写着
`🎯 实时翻译 · 翻译中 · 范围 760×200 @(132,272)`,一眼就知道程序在盯哪里。

- 不想看就关掉:顶栏 **「👁 范围」**,或「🎨 样式」里取消勾选。
- 边框**画在选区外面**(窗口比选区四周各大 4 像素),所以截图识别时**不会把边框
  拍进去**,不影响 OCR;整个框也不吃鼠标点击,不挡下面的程序。
- 「停止翻译」后边框会变成灰色提示「已暂停」。

### 看对话 / 长文:联系上下文翻译

逐句单独翻译时,前后句的指代会断掉。比如前文是部队对话,轮到 `Yes, sir.` 时:

| | 译文 |
| --- | --- |
| 单独翻 | 是的,**先生** |
| 带前文翻 | 是,**长官** |

实时翻译默认开着**上下文翻译**,做法是**翻两遍**:

1. **第一遍(立刻)** —— 新句子一出现就单独翻,马上显示出来,不等上下文;
2. **第二遍(随后)** —— 等这句话稳定约 1 秒,带上**前面几行**重译一次,
   结果不一样就悄悄替换掉。所以你既不会等,又能得到更贴语境的译文。

配合**逐字显示**(大模型边生成边出字),观感上就是"文字刚出现就翻好了"。

- 两个开关都在「🎨 样式 → 上下文与速度」,设置 → 实时翻译里也能改;
- **只对能读懂前文的引擎有效**(DeepSeek、OpenAI 兼容接口)。用 Google / MyMemory
  这类接口时开关不会生效,面板里会直接告诉你;
- 换监视范围会清空上下文,不会串到上一段内容上。

#### 前文是有预算的,不会越滚越大

前文**每翻一句都要重发一次**,不限死的话会一路涨上去:框一大片文字时,一次识别
就可能出来一万多字,全塞进前文的话每翻一句都要多花几千 token,又慢又贵 ——
正好把"秒出"毁掉。所以卡了两道闸:

| 闸 | 配置 | 默认 | 作用 |
| --- | --- | --- | --- |
| 条数 | `rt_context_lines` | 4 句 | 只留最近几句 |
| **字数** | `rt_context_chars` | **500 字** | 真正管住成本的是这道 |

超预算时从**最旧的那句**开始砍,而且保留它的**结尾**部分 —— 离当前这句最近的
内容才最有用。

实测效果(每翻译一句要带的前文):

| 场景 | 不加预算 | 加预算后 |
| --- | --- | --- |
| 字幕(短句) | 229 字 | 229 字(没触发) |
| 长文章(每段 840 字) | 3343 字 ≈ 835 tokens | **500 字 ≈ 125 tokens** |
| 一次框一大片(单条 13500 字) | 13499 字 ≈ 3374 tokens | **499 字 ≈ 124 tokens** |

字数上限在**设置 → 实时翻译 → 前文最多带多少字**里调(100~2000)。
看字幕 300~500 够用;翻长文章可以调到 1000 左右。

> 上下文也有代价:第二遍会多花一次请求。如果只是看单词、短句,可以在样式面板里
> 关掉「联系上下文翻译」。

### 「停止翻译」和「退出实时翻译」不是一回事

- **⏸ 停止翻译** —— 只停轮询。悬浮窗和选区都保留,译文留在屏幕上,按钮变成
  「▶ 继续翻译」,随时接着跑。适合临时停下来看清屏幕上原本的内容。
- **✕ 退出实时翻译** —— 结束整个实时模式。关掉悬浮窗、停止轮询、回到主界面。
  选区和悬浮窗的位置样式都会记住,下次进来默认沿用。

另外顶栏还有 **「⛶ 重选范围」**,不用退出就能换一块监视区域。

### 鼠标穿透怎么退出

开启穿透后悬浮窗收不到鼠标事件(点不到它了)。用快捷键 **`Ctrl+Shift+C`**,
或主界面的「🎯 实时翻译」按钮关掉。

## 二、截屏翻译

1. 点蓝色 **「📷 截屏翻译」**(或按 `Ctrl+Shift+Z`),窗口自动藏起来;
2. 拖动鼠标框选要翻译的文字,松开即开始;
3. 1~2 秒后窗口回来,显示**原文 + 译文**。

- **原文可以直接改** —— OCR 认错字时,改完点「🔁 重新翻译」,不用重新框选;
- **🕘 历史** —— 最近 30 条记录,双击任意一条载入;
- **📋 剪贴板翻译** —— 直接翻剪贴板里的文字;
- 支持多显示器和高分屏(DPI);屏幕上的折行会**自动拼回完整句子**再翻译,不会逐行
  翻译丢上下文。

## 三、翻译引擎

主界面右上角的「引擎」下拉框可以直接切换,或到 **⚙ 设置 → 翻译引擎** 里选。

| 引擎 | 是否需要 Key | 说明 | 获取 Key |
| --- | --- | --- | --- |
| **Google 翻译** | 免费 | 质量好,但**国内直连不了,需自备代理** | — |
| **MyMemory** | 免费 | 国内可直连,适合兜底;单次限 500 字符,填邮箱可提额 | [申请](https://mymemory.translated.net/doc/keygen.php) |
| **LibreTranslate** | 免费 | 开源引擎;公共实例可能要 Key,也可自建实例 | [申请](https://portal.libretranslate.com) |
| **DeepSeek** | **需 Key** | 大模型翻译,译文自然、上下文好,国内直连,按量计费 | [申请](https://platform.deepseek.com/api_keys) |
| **OpenAI 兼容接口** | **需 Key** | 通用适配器,可接硅基流动 / Kimi / 通义 / 本地 Ollama 等 | [申请](https://platform.openai.com/api-keys) |
| **DeepL** | **需 Key** | 译文质量高,免费版每月 50 万字符 | [申请](https://www.deepl.com/pro-api) |

### 需要 Key 的引擎怎么填

1. 选中它(主界面下拉框或设置里都行);
2. 程序**立刻弹出输入框**向你要 Key,里面写清楚了这个引擎的用途;
3. **输入框下方就是「👉 点此获取 Key:网址」**,点一下用浏览器打开申请页;
4. 填好点「**测试并保存**」—— 程序会真连一次接口验证,通过才保存;
5. 填错了翻译时会再提示一次,不会默默失败。

> ⚠ API Key 以**明文**保存在 `config.json`,别把这个文件发给别人。

### 源语言 / 目标语言

主界面「从 [自动检测] 到 [中文(简体)]」可以直接改,设置 → 通用里也能改。

**自动检测是按字符占比判断的。** 程序统计这段文字里各类字符的比例(空格、数字、
标点不参与),哪种文字**过半**就按哪种语言算:

| 文字 | 判定 | 结果(目标 = 中文) |
| --- | --- | --- |
| `今天天气不错,我们出去走走吧` | 汉字 100% | 已经是中文 → 原样显示 |
| `这个 App 很好用` | 汉字 62% | 已经是中文 → 原样显示 |
| `你好 world this is an English sentence` | 拉丁字母 93% | 送去翻译 |
| `苹果 Apple released a new iPhone today` | 拉丁字母 93% | 送去翻译 |
| `12345!!!` | 没有字母 | 不判断,交给引擎 |

> 💡 翻译**很短的句子**(字幕单词、按钮文字、游戏对话)时,把源语言从「自动检测」
> 改成具体语言(比如 `English`)会更准。免费接口的自动检测在短文本上容易认不出语言,
> 于是把原文原样返回,看起来就像"没生效"。

原文本来就是目标语言时(例如中文字幕翻成中文),程序会原样显示,不报错、也不浪费请求。

## 四、OCR 引擎

**⚙ 设置 → 文字识别 OCR**:

| 引擎 | 是否需要 Key | 说明 |
| --- | --- | --- |
| 自动(推荐) | 免费 | 系统 OCR → RapidOCR 依次尝试,配了百度 Key 还会兜底走在线 |
| RapidOCR | 免费 | 内置 PP-OCR 模型,**离线**可用,中英混排效果好,实时翻译推荐 |
| Windows 系统 OCR | 免费 | 最快;需要 Python ≤3.12 且系统装了语言包 |
| Tesseract | 免费 | 需要另外安装 Tesseract-OCR 程序 |
| 百度在线 OCR | **需 Key** | 云端识别,准且快;同样会在下方给出获取 Key 的网址 |

设置页有「🔍 用测试图试一次识别」,可以直接验证当前引擎通不通。

## 常见问题

- **实时翻译卡顿** —— 把框选范围**缩小到只有文字**(越小越快),或把「刷新间隔」调大。
- **实时翻译把自己的译文也识别进去了** —— 程序已处理:悬浮窗和采集区重叠时会先
  把它变透明再截图。更推荐把悬浮窗拖到字幕**上方或下方**不重叠的位置。
- **窗口显示不全 / 看不到下面的按钮** —— 主窗口和设置窗口都能滚:鼠标滚轮,或拖右侧
  滚动条。内容装得下时滚动条会自动隐藏。
- **看不到框选的范围了** —— 顶栏「👁 范围」按钮可以重新显示。
- **一直提示缺 Key** —— 设置里填好后点「🔌 测试连接」,确认通过再保存。
  不同引擎的 Key 不通用,别把 OpenAI 的 Key 填到 DeepSeek 里。
- **翻译失败 / 网络错误** —— 主界面状态栏会显示当前引擎。国内直连不了 Google,
  建议用 MyMemory(免费)或 DeepSeek(需 Key)。失败的引擎会冷却,而且**连续失败会
  指数级拉长冷却时间**(2 → 4 → 8 分钟,最长 30 分钟);本会话成功过的引擎会被优先
  用作兜底,第一次失败之后就能直奔真正能用的那个。
- **短句翻译没生效(译文和原文一样)** —— 免费接口的自动检测在短句上会失灵。程序会
  自动换个源语言重试;想更稳就把「源语言」设成具体语言。
- **框选很宽的一条(字幕条 / 新闻条)识别不出字** —— 这类宽条会被**按行切开逐行识别**,
  比整条丢进去更准。但也更慢,实时翻译建议只框住字幕那一行。
- **识别不出文字** —— 框选时尽量只框文字本身,留一点边距;换个 OCR 引擎再试。
- **日志** —— 运行日志写在 `fanyi.log`。

| 文件 | 作用 |

## 技术实现

- **界面**:Tkinter(系统自带,无额外 UI 依赖)。悬浮窗用 `overrideredirect` 加自绘
  控制条;配色和控件风格集中在 `theme.py`。滚动用 Canvas + inner Frame,
  滚轮按指针位置分发到对应滚动区。
- **截图**:PIL `ImageGrab`,按物理像素 + 虚拟屏幕坐标,支持多屏和 DPI 缩放。
- **实时性**:三层去重 —— ① 先比 24×24 灰度帧签名,画面没变直接跳过 OCR;
  ② 识别文本与上一帧相似度超阈值就沿用上次译文;③ 译文 LRU 缓存,重复句子零请求。
- **OCR**:RapidOCR(PP-OCR 模型,离线)→ Windows `Windows.Media.Ocr` → Tesseract →
  百度在线。RapidOCR 外包了一层处理:宽高比过大时先按**行投影**切成单行再逐行识别,
  绕开它"比例过大就跳过文字检测"的行为。
- **翻译**:长文本按段落分块;某个引擎失败或把原文原样退回时,自动降级到其它引擎
  (优先用本会话成功过的)。应用启动时会先探一遍各引擎,把连不通的标记成冷却,
  免得第一次翻译在已知不通的接口上白等一轮超时。
- **上下文翻译**:实时翻译走两遍 —— 先单独翻立刻显示,等文本稳定后再带前几行重译一次
  (只对大模型引擎)。前文**按条数和字数双重封顶**(默认 4 句 / 500 字),因为它是每句都要
  重发的,不封顶会随内容一路涨上去。流式输出用 SSE 增量回调,边生成边刷新悬浮窗。
- **语言判定**:按各书写系统的字符占比判断(过半才算),中英混排不会被误判成中文。
- **鼠标穿透**:Win32 `WS_EX_TRANSPARENT | WS_EX_LAYERED`。
- **监视范围框**:`wm attributes -transparentcolor` 色键透明,边框画在选区外的留白里,
  看得见却不会被自己拍到。
- **线程模型**:Tk 主线程截图和画界面,OCR 与翻译在后台线程,结果经 queue 回主线程。
